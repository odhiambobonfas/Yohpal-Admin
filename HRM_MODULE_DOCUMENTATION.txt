3. HRM MODULE FEATURES
================================================================================

The HRM module manages 6 core areas:

1. DEPARTMENTS MANAGEMENT
   - Create, read, update, delete departments
   - Assign department heads
   - Track department codes

2. EMPLOYEE DESIGNATIONS
   - Manage job titles/positions
   - Set basic salary per designation
   - Unique designation codes

3. ATTENDANCE TRACKING
   - Clock in/out times
   - Multiple shift support
   - Attendance status (present, absent, leave, holiday)
   - Custom shift creation

4. HOLIDAY MANAGEMENT
   - Public holidays
   - Company holidays
   - Custom holiday types
   - Date range support

5. LEAVE MANAGEMENT
   - Multiple leave types (annual, sick, maternity, etc.)
   - Leave request workflow
   - Approval system (pending, approved, rejected)
   - File attachment support

6. PAYROLL SYSTEM
   - Payment components (earnings/deductions)
   - Tax brackets
   - Contribution tiers
   - Flexible rate types (value/percentage)

6. BACKEND WORKFLOW
================================================================================

--------------------------------------------------------------------------------
6.1 REQUEST FLOW
--------------------------------------------------------------------------------

1. Client Request
   ↓
2. Express Router (routes/app.js)
   ↓
3. Authentication Middleware (authMiddleware)
   - Validates JWT token
   - Checks session
   ↓
4. Permission Middleware (hasPermission)
   - Checks user role permissions
   ↓
5. Controller (HRMController)
   - Validates input
   - Processes business logic
   ↓
6. Utility Layer (HRMUtil/PayrollUtil)
   - Database operations
   - Cache management
   ↓
7. Model Layer (Firestore)
   - Data persistence
   ↓
8. Response to Client


--------------------------------------------------------------------------------
6.2 DEPARTMENT CREATION WORKFLOW
--------------------------------------------------------------------------------

POST /department/create
↓
HRMController.createDepartment()
  - Extract request body
  - Get logged-in user info
  - Validate departmentName (required, not empty)
  - Validate departmentCode (max 10 chars)
  - Validate departmentDescription (max 500 chars)
  ↓
HRMUtil.createDepartmentQuery()
  - Check duplicate departmentName in Firestore
  - Check duplicate departmentCode in Firestore
  - Build payload with metadata (addedBy, timestamps)
  - Insert into Firestore 'departments' collection
  - Clear Redis cache for departments
  ↓
Return success response with new department ID


--------------------------------------------------------------------------------
6.3 ATTENDANCE RETRIEVAL WORKFLOW
--------------------------------------------------------------------------------

GET /employee/attendance
↓
HRMController.employeeAttendance()
  - Check if AJAX request
  ↓
HRMUtil.getAllAttendanceRecords()
  - Generate cache key: 'yp:attendances:filtered'
  - Check Redis cache
  - If cache miss:
    ↓
    - Query Firestore 'attendance' collection
    - Order by attendanceDate DESC
    - Fetch all records
    - For each record:
      - Resolve userRef to get employee details
      - Attach user object to attendance record
    - Store in Redis (TTL: 100 seconds)
  - Return cached/fresh data
  ↓
mexDtParser (DataTables formatter)
  - Format columns (Employee, Date, Status, etc.)
  - Add action buttons based on permissions
  - Return formatted data
  ↓
Return JSON response


--------------------------------------------------------------------------------
6.4 LEAVE REQUEST WITH FILE UPLOAD WORKFLOW
--------------------------------------------------------------------------------

POST /leaves/create (multipart/form-data)
↓
Multer Middleware
  - Process file upload (leaveAttachment)
  - Store temporarily
  ↓
HRMController.createLeaveRequest()
  - Validate employeeId
  - Validate dates (startDate, endDate)
  - Validate leaveType
  - Validate reason (required, max 500 chars)
  ↓
File Upload Processing
  - handleFileUploads() → Save to local: public/store/docs/hrm/leaves/
  - FirebaseUtility.uploadFile() → Upload to Firebase Storage
  - Get public URL from Firebase
  ↓
HRMUtil.createLeaveRequestQuery()
  - Build payload with:
    - userId, userRef (Firestore reference)
    - leaveType, dates, reason
    - attachmentLocalPath (local path)
    - fbAttachmentFbPath (Firebase URL)
    - status: 'pending'
  - Insert into Firestore 'leaves' collection
  - Clear Redis cache
  ↓
Return success response


--------------------------------------------------------------------------------
6.5 PAYROLL BRACKET CREATION WORKFLOW
--------------------------------------------------------------------------------

POST /payroll/brackets/create
↓
HRMController.createBracketScope()
  - Validate componentId (required)
  - Validate bracketName (required)
  - Validate bracketCode (max 50 chars)
  - Validate minRange (number >= 0)
  - Validate maxRange (>= minRange)
  - Validate employeeRate (number >= 0)
  - Validate employeeRateType (value/percentage)
  ↓
PayrollUtil.createPaymentBracketQuery()
  - Check duplicate bracketName
  - Check duplicate bracketCode
  - Build payload with:
    - componentId, componentRef (Firestore reference)
    - bracket details
    - scope: 'bracket'
  - Insert into 'componentEssentials' collection
  - Clear Redis cache: 'yp:componentBrackets:filtered'
  ↓
Return success response

7. SECURITY & VALIDATION
================================================================================

--------------------------------------------------------------------------------
7.1 AUTHENTICATION
--------------------------------------------------------------------------------

JWT Token:
- Generated on login
- Stored in session
- Expires in 3 days (configurable)
- Secret: JWT_SECRET from .env

Session:
- Storage: Redis or Memory
- Session name: yohpal_admin_sess
- TTL: 360000 seconds
- Secure cookies in production

Middleware Chain:
Request → authMiddleware → routeMiddleware → Controller


--------------------------------------------------------------------------------
7.2 AUTHORIZATION (RBAC)
--------------------------------------------------------------------------------

Permission Format: "module.resource.action"
Examples:
- hrm.departments.view
- hrm.departments.create
- hrm.departments.edit
- hrm.departments.delete
- hrm.attendance.create
- hrm.payroll.view

Permission Check:
hasPermission(user.permissions, 'hrm.departments.create')

Role Hierarchy:
- Super Admin: All permissions
- Admin: Most permissions
- Manager: Department-specific permissions
- Employee: Limited permissions


--------------------------------------------------------------------------------
7.3 INPUT VALIDATION
--------------------------------------------------------------------------------

String Validations:
- Required fields: Check for null/undefined/empty
- Max length: departmentCode (10), description (500)
- Trim whitespace
- Unique constraints checked in database

Number Validations:
- Type check: isNaN()
- Range check: >= 0 for amounts
- Comparison: maxRange >= minRange

Date Validations:
- Valid date: isNaN(new Date(date).getTime())
- Date comparison: endDate >= startDate

Enum Validations:
- componentType: ['earning', 'deduction']
- componentScope: ['none', 'tier', 'bracket']
- status: ['pending', 'approved', 'rejected']
- leaveType: predefined list


--------------------------------------------------------------------------------
7.4 FILE UPLOAD SECURITY
--------------------------------------------------------------------------------

Multer Configuration:
- Max file size: 5MB
- Allowed types: image/png, image/jpeg, application/pdf
- Storage: Local + Firebase Storage
- Filename: Auto-renamed with timestamp

Upload Path:
Local: public/store/docs/hrm/leaves/
Firebase: company/yohpal/hrm/leaves/

Validation:
- File type check
- Size limit enforcement
- Virus scanning (recommended for production)


--------------------------------------------------------------------------------
7.5 ERROR HANDLING

Custom Exception Class:

Error Response Format:

8. CACHING STRATEGY
================================================================================

--------------------------------------------------------------------------------
8.1 REDIS CACHE CONFIGURATION
--------------------------------------------------------------------------------

Connection:
- Host: REDIS_URL from .env
- Port: REDIS_PORT (default 14000)
- Password: REDIS_PASSWORD
- Timeout: 10000ms

Cache Key Format:
- yp:departments:filtered
- yp:designations:filtered
- yp:attendances:filtered
- yp:holidays:filtered
- yp:paymentComponents:filtered
- yp:componentBrackets:filtered


--------------------------------------------------------------------------------
8.2 CACHE TTL (Time To Live)
--------------------------------------------------------------------------------

Long-lived (3600-7200 seconds):
- Departments: 3600s (1 hour)
- Designations: 3600s (1 hour)
- Holidays: 3600s (1 hour)
- Payment Components: 7200s (2 hours)

Short-lived (100 seconds):
- Attendance: 100s (frequently updated)
- Leave Requests: 100s (frequently updated)


--------------------------------------------------------------------------------
8.3 CACHE INVALIDATION
--------------------------------------------------------------------------------

Manual Invalidation:
- On create: redis.deleteFunc(cacheKey)
- On update: redis.deleteFunc(cacheKey)
- On delete: redis.deleteFunc(cacheKey)

Filter-based Invalidation:
- Store filters in: yp:departments:filters
- Compare current vs cached filters
- Invalidate if filters changed

Cache Refresh:
redis.cacheParser(key, fetchFunction, ttl)
- Checks cache first
- If miss, executes fetchFunction
- Stores result with TTL

9. FILE UPLOAD HANDLING
================================================================================

--------------------------------------------------------------------------------
9.1 LOCAL FILE STORAGE
--------------------------------------------------------------------------------

Function: handleFileUploads(req, subfolder)

Process:
1. Extract file from req.file
2. Generate unique filename with timestamp
3. Create directory if not exists
4. Save file to: public/store/{subfolder}/
5. Return relative path

Example:
handleFileUploads(req, 'docs/hrm/leaves')
→ public/store/docs/hrm/leaves/1234567890-document.pdf


--------------------------------------------------------------------------------
9.2 FIREBASE STORAGE
--------------------------------------------------------------------------------

Class: FirebaseUtility

Method: uploadFile(localPath, firebasePath, options)

Process:
1. Read file from local path
2. Upload to Firebase Storage bucket
3. Set metadata (contentType, cacheControl)
4. Make file public (if makePublic: true)
5. Return public URL

Example:
await FBUTIL.uploadFile(
  'public/store/docs/hrm/leaves/file.pdf',
  'company/yohpal/hrm/leaves',
  { linkType: 'firebase', makePublic: true }
)
→ https://storage.googleapis.com/bucket/company/yohpal/hrm/leaves/file.pdf


--------------------------------------------------------------------------------
9.3 FILE CLEANUP
--------------------------------------------------------------------------------

Recommendation:
- Implement cron job to delete old local files
- Keep Firebase Storage as source of truth
- Delete local files after successful Firebase upload
